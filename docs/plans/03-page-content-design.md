# خطة تصميم محتوى الصفحات — Deken

**الإصدار:** 1.5  
**التاريخ:** 2026-04-24  
**سجل مختصر:** 1.1 — لوحة التحكم. 1.2 — نقطة البيع. 1.3 — المنتجات. 1.4 — الديون. 1.5 — التقارير والإعدادات (`ReportsPage`, `SettingsPage`, `reports.*`, `settings.*`).

**المرجع:** يفصّل [المرحلة 3 في خارطة 02](./02-implementation-roadmap.md) على مستوى **كل مسار**؛ التنفيذ في الكود بدون منطق قاعدة بيانات حتى إشعار آخر.

## الهدف

لكل صفحة رئيسية: **تخطيط محتوى واضح**، **مكوّنات UI**، **نصوص i18n (ar + en)**، **حالات فارغة/تحميل**، و**بيانات وهمية** حيث يلزم — ثم استبدال `PlaceholderPage` بصفحة مخصّصة عند اكتمال تصميم المحتوى لتلك الصفحة.

## كيفية التتبع

- عند إنهاء تصميم محتوى صفحة: ضع **`[x]`** على كل بند تابع لها في هذا الملف، وارفع التغيير مع Git.
- مفاتيح الترجمة: **`dashboard.*`**, **`pos.*`**, **`products.*`**, **`debts.*`**, **`reports.*`**, **`settings.*`** — لجميع المسارات الرئيسية الحالية (تجنّب تكرار نصوص طويلة تحت `pages.*` إلا للـ placeholders المؤقتة).

## مبادئ مشتركة (قبل إغلاق أي صفحة)

- [x] لا نصوص «hard-coded» في JSX — كل ما يظهر للمستخدم عبر i18n.
- [x] التخطيط يستخدم خصائص منطقية (RTL/LTR) ولا ينكسر عند تبديل اللغة.
- [x] الألوان والمسافات من **tokens** في `index.css` / CSS الصفحة حيث يناسب.
