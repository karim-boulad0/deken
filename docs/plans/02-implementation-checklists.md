# تتبع تنفيذ خارطة 02 — قوائم مهام (Markdown)

**الغرض:** تتبع تقدّم [02-implementation-roadmap.md](./02-implementation-roadmap.md) داخل المستودع.  
**الطريقة:** حوّل `- [ ]` إلى `- [x]` عند إنجاز المهمة، وارفع التغيير مع Git ليبقى التاريخ واضحاً.

---

## Phase 1 — Bootstrap (المرحلة 1: تسطيب وتشغيل)

**معيار إغلاق المرحلة:** تثبيت نظيف → `npm run dev` → نافذة Electron تفتح بدون خطوات غير موثقة.

### هيكل المشروع والأدوات

- [x] وجود `package.json` في جذر المستودع مع تسمية المشروع (`deken` أو ما يُتفق عليه).
- [x] اختيار مدير حزم واحد **موثّق** في `docs/guides/dev-setup.md` (مثلاً `pnpm` أو `npm`) والالتزام به في التعليمات.
- [x] ملف `.gitignore` يغطي على الأقل: `node_modules/`، مجلدات البناء (`dist/`، `out/`، `release/` أو ما يولّده القالب)، ملفات بيئة محلية (`.env*.local`).

### Vite + React + TypeScript (الواجهة)

- [x] تهيئة **Vite** لمشروع React مع **TypeScript**.
- [x] `tsconfig` مناسب (مثلاً `strict` أو سياسة واضحة موثقة).
- [x] نقطة دخول Renderer تعمل في المتصفح/Vite أثناء التطوير.

### Electron

- [x] عملية **Main** (`main` process) منفصلة عن الواجهة.
- [x] ملف **preload** (أو سياسة أمان IPC موثقة) — تجنّب `nodeIntegration: true` في Renderer إلا بقرار معلمّ في `docs/architecture/`.
- [x] ربط التطوير: تشغيل Vite + فتح نافذة Electron تشير إلى خادم التطوير (أو مسار مكافئ يعمل).

### السكربتات

- [x] `dev` — تشغيل بيئة التطوير (إعادة تحميل سريعة للواجهة حيث ينطبق).
- [x] `build` — بناء نسخة قابلة للتعبئة/التوزيع **أو** بناء مبدئي موثّق كخطوة أولى مع قائمة “لاحقاً للتعبئة الكاملة” إن كان القالب يتدرج.

### جودة الكود (Lint / Format)

- [x] **ESLint** مع دعم TypeScript وReact (ومنها `react-hooks` حيث ينطبق).
- [x] **Prettier** + عدم تعارض مع ESLint (`eslint-config-prettier` أو ما يعادله).
- [x] سكربت `lint` (ويفضّل `lint:fix` أو `format` إن رغبت) في `package.json`.

### التحقق والتوثيق

- [x] اختبار **تثبيت نظيف** (حذف `node_modules` + lock إن لزم، ثم تثبيت من الصفر) ثم `dev` بنجاح.
- [x] إنشاء/تحديث [../guides/dev-setup.md](../guides/dev-setup.md): المتطلبات (Node إصدار)، الأوامر، ملاحظات ويندوز إن لزم.
