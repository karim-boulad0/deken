# قواعد تنظيم المستودع والتوثيق (`docs/`)

هذه القواعد إلزامية حتى تبقى **كل جلسة Cursor** على نفس المسار: مجلدات واضحة، بدون تشتيت.

## فلسفة التنظيم

- **كل نوع محتوى له مجلد مخصص** — لا تُكدس الخطط والأدلة وقرارات التصميم في مكان واحد.
- **قواعد الوكيل (Cursor)** تبقى **حصراً** في `.cursor/rules/*.mdc` — لا تُنقل إلى `docs/` كبديل تقني؛ `docs/` يشرح أين القواعد ويشير إليها فقط.
- **مدخل الجلسة الجديدة**: جذر المستودع `AGENTS.md` يحدد ترتيب القراءة والثوابت؛ عند إضافة مسار مهم جديد، راجع `AGENTS.md` إن لزم سطراً في “خريطة مختصرة”.

## هيكل `docs/` المعتمد

```
docs/
  README.md                 # فهرس عام لكل التوثيق
  STRUCTURE.md              # هذا الملف
  plans/
    README.md               # فهرس الخطط فقط — يُحدَّث مع كل خطة جديدة
    01-master-plan.md       # مثال: الخطة الرئيسية
    future-reminders.md     # تذكيرات لاحقة (مخالف لترقيم 01/02 إن رغبت)
  architecture/             # ADR، مخططات، قرارات تقنية “لماذا”
  guides/                   # أدلة مطور / مستخدم نهائي، إجراءات تشغيل
```

## ماذا يوضع أين

| المجلد               | يُوضع فيه                                       | لا يُوضع فيه               |
| -------------------- | ----------------------------------------------- | -------------------------- |
| `docs/plans/`        | رؤية المنتج، مراحل، تفصيل ميزات على مستوى الخطة | كود، سكربتات بناء          |
| `docs/architecture/` | ADR، مخططات تدفق، عقود IPC مقترحة               | خطة تسويق طويلة            |
| `docs/guides/`       | “كيف أشغّل المشروع”، “كيف أبني الإصدار”         | الخطة الاستراتيجية الكاملة |

## التسمية

- **إنجليزي صغير مع شرطات**: `01-master-plan.md`, `adr-001-sqlite.md`.
- **بادئة رقمية** في `docs/plans/` عند الترتيب: `01-`, `02-`.
- تجنّب المسافات في أسماء الملفات والمجلدات.

## المحتوى (Markdown)

- عنوان `#` واحد في أول الملف؛ ملخص قصير بعده للمستندات الطويلة.
- روابط **نسبية** بين ملفات `docs/` فقط.
- اتساق المصطلحات التقنية (POS، SQLite، i18n).

## التحديثات والفهرسة

- لا تحذف مستندات تاريخية دون إشارة في `README.md` أو “مُستبدَل بـ …”.
- خطة جديدة في `plans/`: حدّث `docs/plans/README.md` **و** `docs/README.md` إن كانت مرجعية عامة.
- تغيير هيكلي (مجلد جديد تحت `docs/`): حدّث **هذا الملف** أولاً، ثم `AGENTS.md` إن لزم.

## العلاقة بقواعد Cursor

| الملف                                       | الغرض                                        |
| ------------------------------------------- | -------------------------------------------- |
| `.cursor/rules/deken-core.mdc`              | أهداف المنتج، كود، i18n، ترحيلات             |
| `.cursor/rules/deken-repository-layout.mdc` | مسارات المجلدات في المستودع والكود المستقبلي |
| `.cursor/rules/deken-documentation.mdc`     | يُفعَّل عند العمل على `docs/**/*.md`         |

أي قاعدة جديدة للوكيل: أضف `.mdc` تحت `.cursor/rules/` واذكرها هنا أو في `AGENTS.md` إن كانت تغيّر مسار البداية.
